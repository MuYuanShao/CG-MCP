# 采购订单管理模块 (spd-order)

## 模块定位

承接采购计划生成的订单，覆盖订单确认、发货、物流跟踪、到货通知与下游验收衔接，保障采购履约过程可追溯。

## 功能说明

| 功能 | 说明 |
|------|------|
| 订单创建 | 支持由采购计划转订单，也支持手工创建订单，记录医院、供应商、商品明细、数量、价格与交付要求 |
| 订单确认 | 供应商确认订单内容，支持整单确认、部分确认、驳回与备注说明 |
| 发货管理 | 按订单明细创建发货单，登记批号、效期、UDI、物流信息和发货数量 |
| 物流跟踪 | 维护物流公司、运单号、发货时间、预计到达时间和签收状态 |
| 到货通知 | 发货后通知医院或院内验收人员，为验收单创建提供订单与发货明细 |
| 异常处理 | 支持缺货、数量差异、订单取消、发货撤回、物流异常等处理 |

## 核心API

```java
// 订单分页查询
GET /api/order/page?pageNum=1&pageSize=10&orderNo=xxx&hospitalId=xxx&status=1

// 根据采购计划创建订单
POST /api/order/from-plan
Body: {planId, hospitalId, deliveryAddressId, expectedDeliveryDate, itemIds}

// 手工创建订单
POST /api/order
Body: {hospitalId, deliveryAddressId, expectedDeliveryDate, items: [{productId, quantity, price}]}

// 订单确认
PUT /api/order/{id}/confirm
Body: {confirmStatus, confirmRemark, items: [{orderItemId, confirmQty, reason}]}

// 创建发货单
POST /api/order/{id}/shipment
Body: {shipmentNo, logisticsCompany, trackingNo, shipDate, items: [{orderItemId, batchNo, expireDate, udiCode, shipQty}]}

// 更新物流信息
PUT /api/order/{id}/logistics
Body: {logisticsCompany, trackingNo, logisticsStatus, estimatedArrivalTime, remark}

// 取消订单
PUT /api/order/{id}/cancel
Body: {cancelReason}

// 获取订单明细
GET /api/order/{id}/items
```

## 订单状态流转

```
待确认 -> 已确认 -> 待发货 -> 已发货 -> 已到货 -> 已验收 -> 已完成
   |         |          |          |
   |         |          |          -> 物流异常 -> 已发货
   |         |          -> 发货撤回 -> 待发货
   |         -> 驳回 -> 已驳回
   -> 取消 -> 已取消
```

## 业务流程

```
采购计划确认 -> 生成采购订单 -> 供应商确认 -> 创建发货单 -> 更新物流 -> 到货通知 -> 院内验收 -> 库存入库 -> 结算生成
```

## 关键业务规则

| 规则 | 说明 |
|------|------|
| 订单来源 | 由采购计划生成的订单必须保留 `planId`，用于回溯采购计划执行情况 |
| 数量控制 | 发货数量不得超过确认数量，部分发货时需记录剩余待发数量 |
| 证照校验 | 发货前需校验商品、供应商、医院相关证照是否有效 |
| UDI校验 | 医疗器械类商品发货明细必须记录 UDI 或明确豁免原因 |
| 状态限制 | 已验收、已完成、已取消订单不得继续编辑订单明细 |
| 下游触发 | 已发货订单可生成到货通知，验收通过后触发库存入库与结算准备 |

### 采购订单编辑弹窗

#### 弹窗布局

```
┌───────────────────────────────────────────────────────────────┐
│ 新增采购订单                                             [×]    │
├───────────────────────────────────────────────────────────────┤
│ 基本信息: 医院* 收货地址* 预计到货日期* 订单备注                 │
│ 商品明细: [添加商品]                                           │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │ 商品编码 商品名称 规格 单位 数量 单价 金额 证照状态 操作       │ │
│ └───────────────────────────────────────────────────────────┘ │
│ 合计金额: 0.00                                                │
│                                      [取消] [保存] [提交确认]    │
└───────────────────────────────────────────────────────────────┘
```

#### 表单字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 医院 | 下拉选择 | 是 | 从已合作医院列表读取 |
| 收货地址 | 下拉选择 | 是 | 根据医院联动展示可用收货地址 |
| 预计到货日期 | 日期 | 是 | 不得早于当前日期 |
| 商品明细 | 表格 | 是 | 至少包含一条商品明细 |
| 数量 | 数字 | 是 | 必须大于 0 |
| 单价 | 数字 | 是 | 不得小于 0 |
| 备注 | 多行文本 | 否 | 记录交付要求或特殊说明 |

#### 弹窗操作按钮

| 按钮 | 功能说明 |
|------|----------|
| 取消 | 关闭弹窗，不保存修改 |
| 保存 | 保存为草稿或待确认订单 |
| 提交确认 | 保存订单并流转到待确认状态 |

#### 提交校验规则

- 医院、收货地址、预计到货日期、商品明细不能为空。
- 商品数量必须大于 0，单价不得小于 0。
- 同一订单中相同商品、规格、批次维度应合并或提示用户确认。
- 提交前需校验商品状态、证照状态、医院授权关系和供应商合作状态。

### 发货单编辑弹窗

#### 弹窗布局

```
┌───────────────────────────────────────────────────────────────┐
│ 创建发货单 - DD20240001                                  [×]    │
├───────────────────────────────────────────────────────────────┤
│ 物流信息: 物流公司* 运单号* 发货日期* 预计到达时间                │
│ 发货明细:                                                       │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │ 商品编码 商品名称 待发数量 本次发货 批号 效期 UDI 操作          │ │
│ └───────────────────────────────────────────────────────────┘ │
│                                      [取消] [保存] [确认发货]    │
└───────────────────────────────────────────────────────────────┘
```

#### 表单字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 物流公司 | 输入/下拉 | 是 | 记录承运方 |
| 运单号 | 文本 | 是 | 同一物流公司下不可重复 |
| 发货日期 | 日期 | 是 | 不得晚于当前日期之后的业务允许范围 |
| 发货数量 | 数字 | 是 | 不得超过待发数量 |
| 批号 | 文本 | 是 | 用于批次库存与追溯 |
| 效期 | 日期 | 是 | 不得早于发货日期 |
| UDI | 文本 | 条件必填 | 医疗器械商品必填或记录豁免原因 |

#### 弹窗操作按钮

| 按钮 | 功能说明 |
|------|----------|
| 取消 | 关闭弹窗，不保存修改 |
| 保存 | 保存发货单草稿 |
| 确认发货 | 校验发货明细并将订单流转为已发货或部分发货 |

#### 提交校验规则

- 物流公司、运单号、发货日期不能为空。
- 发货明细至少包含一条本次发货数量大于 0 的商品。
- 本次发货数量不得超过订单剩余待发数量。
- 批号、效期、UDI 需满足商品追溯和合规要求。
- 确认发货成功后生成到货通知，并允许验收模块读取发货明细。
